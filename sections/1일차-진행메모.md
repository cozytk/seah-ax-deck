## 수업 전 준비

- Windows에서 Claude 로그인·앱·Git for Windows·Node.js LTS 확인. 터미널 시연용 Claude Code CLI는 별도 확인한다.
- 모델은 계정에 보이는 Opus 우선, 한도가 부족하면 Sonnet. 비교 실습 A/B에서는 같은 모델과 설정을 유지한다.
- [CLAUDE.md 비교 ZIP](https://cozytk.github.io/seah-ax-deck/downloads/claudemd-lab.zip)과 [엑셀·Windows MCP ZIP](https://cozytk.github.io/seah-ax-deck/downloads/day1-samples.zip)을 미리 내려받는다.
- 원격 접속은 강사 계정으로 기능을 설명하고, 학생의 회사 PC에 원격 연결을 즉석에서 열지 않는다. 조직 설정과 허용된 계정 범위를 확인한 뒤 선택 실습한다.
- Vercel 계정·저장소, GCP 결제·API·IAM이 준비된 프로젝트를 강사가 사용한다. GCP 권한 문제 해결은 수업 필수 과제로 두지 않는다.
- 기존 앱 캡처에는 Windows 외 환경도 포함한다. Windows 단축키 안내를 우선한다. Hermes·Grok Bot 이미지는 공식 웹페이지 캡처이며 로그인 후 제품 실측 화면은 아니다.

## CLAUDE.md 비교 실습 · 15분

1. 준비 3분: before/after에는 같은 현장메모.txt. 자동 메모리는 비교 동안 끄고 기존 설정을 기록한다. /context에서 상위·개인 지침도 확인한다.
2. 응답 A 3분: before 새 세션에서 「현장메모.txt를 읽고 주간 보고 초안을 만들어줘.」
3. 지침 작성 4분: after/CLAUDE.md에 네 규칙 저장. CLAUDE.md.txt가 아닌지 확인한다.
4. 응답 B·비교 5분: after 새 세션, 같은 모델·요청. 읽힌 파일, 제목 순서, 12분 조치 대상, 전체 24분, 미확인 원인을 확인한다. 마지막에 자동 메모리 설정 복구.

차이가 없다고 실패가 아니다. 단일 A/B로 성능·비용 개선을 단정하지 않는다. 읽힌 경로가 맞는지와 팀 기준을 지켰는지가 이번 실습의 확인 대상이다.

## Agent Teams · 강사 시연

현장메모.txt를 복사한 별도 시연 폴더에서 PowerShell 실행. CLI 설치·로그인 → 환경 변수 → in-process 시작 → 수치 담당과 누락 담당 요청. 기존 캡처와 달리 최신 버전은 팀 생성·삭제를 따로 시킬 필요가 없다. 패널과 작업 목록에서 팀원을 확인하고 종료 요청 후 세션을 끝낸다. 사용량이 더 들므로 학생 전원에게 실행시키지는 않는다.

## 구현 실습에서 확인할 것

엑셀 A라인 100개 중 4개, B라인 200개 중 2개이므로 전체 불량률은 2%다. 2.5%는 비율의 단순 평균이다. PRD의 완료 조건에 전체 2%, A라인 4%, 필수 열 누락 안내를 남긴다.

스킬 이름을 입력한 것과 실제로 읽은 것은 구분한다. 설치 파일과 작업 기록을 확인한다. Playwright MCP도 연결 표시와 실제 브라우저 호출을 구분한다. 배포 주소에서 같은 샘플을 다시 검사한다.

한도·네트워크·설치 문제로 실행하지 못하면 짝이나 강사 화면을 보고 검증 지시를 작성한다. 실행하지 못한 항목은 미검증으로 기록한다.
