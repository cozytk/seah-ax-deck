## 1. 기존 DESIGN.md 가 이미 하고 있던 것

**이게 이 사례의 절반이다.** 셀프리뷰가 아래 항목에서는 한 건도 잡지 못했다.

| 항목 | 문서에 있던 말 | 코드의 상태 |
|---|---|---|
| **색만으로 구분하지 않기** | 「판정은 이 도구의 결론이다. 색만으로 구분하지 않는다」 | 판정 띠 옆에 항상 글자, 분포 막대 아래에 숫자, 마감은 게이지 + `D-n` |
| **숫자 자릿수** | 「모든 숫자는 `tabular-nums`」 | `.tnum` 이 표·카드·이력에 빠짐없이 |
| **표 가로 스크롤** | 「표는 자기 컨테이너 안에서 가로 스크롤한다」 | `overflow-x-auto` + `min-w-[900px]`, `body` 가 안 밀린다 |
| **정보 위계** | 「화면의 무게중심」 절 전체 | 숫자 44px / 라벨 11px, 판단불가가 부적합보다 강함 |
| **빈 화면·못 읽은 값** | 「비워두지 않는다」 | `읽지 못함` · `D-?` · 빈 표 문구가 전부 문장으로 |

여기에 문서에 안 적혀 있었는데도 코드가 맞게 한 것이 셋 더 있었다.
행 클릭을 `<tr onClick>` 이 아니라 링크 오버레이로 깐 것(키보드로 닿는다),
`aria-current="page"`, 검토 보드 `<select>` 의 `sr-only` 라벨.

**PRD 디자인 4항목 중 색·타이포·정보 위계는 이 문서가 이미 다 옮겼다.**
남은 하나가 접근성이었다.

## 2. 그런데도 빠져 있던 것

보강 전 DESIGN.md 는 272줄이었다. 색 표가 넷, 글자 크기 표가 하나,
「하지 않는 것」이 여덟 줄 있다. 그런데 아래는 **한 줄도 없었다.**

| 빠진 것 | 왜 안 걸렸나 |
|---|---|
| **건너뛰기 링크** | 화면에 안 보이는 것이라 「디자인」으로 안 세어진다 |
| **초점 표시** | `* { outline-ring/50 }` 이 **색만** 정한다. 굵기는 브라우저 기본값에 맡겨져 있었다 |
| **명암비 하한** | 색은 정교하게 정해놓고 「몇 대 몇 이상」이 없다. 그래서 11px 라벨이 **3.1:1** 이었다 |
| **`prefers-reduced-motion`** | 문서는 「애니메이션 안 쓴다」고 적었는데 코드에는 전환이 세 군데 있었다. **문서와 코드가 갈렸는데 아무도 안 봤다** |
| **`color-scheme` · `theme-color`** | 다크 팔레트를 통째로 정의해두고 브라우저에 알리는 한 줄이 없다 |
| `h1` | 네 화면 모두 `h2` 부터 시작한다. 낭독기로 훑으면 화면 구분이 안 된다 |
| 막대의 대체 문구 | `aria-hidden` 은 붙였는데 대신 읽을 말을 안 줬다 |

### Tab 한 번의 차이

`before-tab.png` — 첫 Tab 이 곧장 왼쪽 메뉴 「오늘 브리핑」으로 들어간다.
**표에 닿으려면 메뉴 네 개를 더 지나야 한다.**

`after-tab.png` — 왼쪽 위에 **「본문으로 건너뛰기」**가 흰 테두리와 함께 뜬다.

여기서 헷갈리지 말아야 할 게 있다. 메뉴에 뜬 테두리 자체는 원래도 보였다 —
확대해 보면 밝은 바탕 위의 남색 테두리라 읽힌다. **문제는 그게 보장된 게 아니었다는 것이다.**
색만 정해두고 굵기는 브라우저에 맡겨져 있었고, 색도 `--ring` 의 50%였다.
같은 규칙이 어두운 상단 바 위에 오면 남색 바탕에 남색 테두리가 된다.

실제로 그랬다. 처음 찍은 `after-tab` 에서 건너뛰기 링크의 테두리가 상단 바에 묻혔고,
이미지를 열어보고서야 알았다. 그래서 **어두운 바 위에 뜨는 것만 흰 테두리**로 예외를 뒀다.

## 3. 셀프리뷰가 잡아낸 것 중 미리 생각 못 했던 것

작업 전에 확인할 항목을 여덟 개 적어뒀다 —
건너뛰기 · `:focus-visible` · `prefers-reduced-motion` · 대체 텍스트 ·
`tabular-nums` · `color-scheme` · 표 가로 스크롤 · 색만으로 구분하지 않기.

그 목록에 **없던** 것이 셋 나왔다.

### 3-1. 명암비 — 유일하게 DESIGN.md 의 값을 고쳐야 했던 항목

여덟 개 목록에 없었는데 가장 많이 걸렸다. 셋이 4.5:1 미만이었다.

| 색 | 쓰이는 곳 | 잰 값 | 바꾼 값 |
|---|---|---|---|
| `--faint` `#8C949E` | **11px 라벨 전부**, 표 머리 | 3.1:1 | `#6B7480` (4.8:1) |
| `--v-unfit` `#8C949E` | 부적합 판정 글자 | 3.1:1 | `#6B7480` (4.8:1) |
| `--v-cond` `#B26A00` | 조건부 판정, D-7 | 4.3:1 | `#A05F00` (5.1:1) |

**하필 시그니처가 걸렸다.** 「작고 흐린 11px 라벨」이 이 화면의 리듬인데,
흐리게 만드는 방향과 읽히게 만드는 방향이 정면으로 부딪힌다.
리듬을 색이 아니라 크기·자간으로 낸다는 원칙은 문서에 이미 있었으므로,
색만 한 단계 내리고 크기·자간은 그대로 뒀다. `before-top` 과 `after-top` 을
나란히 놓으면 차이를 찾기 어렵다.

부적합은 여전히 화면에서 가장 흐린 글자다. **순서는 안 바뀌었다.**

### 3-2. 지침을 지켰는데도 남은 구멍 — 가로 스크롤

「표는 자기 컨테이너 안에서 가로 스크롤한다」는 문서에 있었고 코드도 지켰다.
그런데 `overflow-x: auto` 만으로는 **마우스 없이 표를 밀 방법이 없다.**
`role="region"` + `tabindex="0"` + 이름을 같이 줘야 그 영역이 초점 대상이 되고 방향키가 먹는다.

「표 안에 링크가 있으니 Tab 으로 밀린다」는 반박이 가능한데, 발주기관·규격·수량 칸에는
링크가 없다. 그 칸들은 마우스 없이 볼 방법이 없었다.
대신 **표마다 Tab 정거장이 하나씩 늘어난다.** 1440 폭에서는 표가 안 넘치니 헛걸음이다.
넘칠 때만 켜려면 폭을 재야 하고, 그건 그것대로 안 좋다. 헛걸음 쪽을 골랐다.

지침 한 줄을 정확히 따랐는데도 구멍이 남은 자리다.

### 3-3. 시그니처 표기가 그대로 접근성 문제가 되는 자리

`D-2` 는 눈으로는 한 덩어리인데 낭독기는 「디 마이너스 이」로 읽는다.
표기를 바꾸면 「색 띠를 세로로 훑는다」는 설계가 무너지므로,
보이는 표기는 그대로 두고 `sr-only` 로 「마감까지 2일」을 하나 더 깔았다.

그 밖에 반쯤 되어 있던 것도 나왔다 — 수집 상태 띠에는 `role="status"` 가 이미 붙어 있었는데
같은 화면의 「불러오는 중…」에는 없었다.

## 4. 고친 것 (전체)

기능과 시그니처는 건드리지 않았다. E2E 12개가 손대기 전후 그대로 통과한다.

| 파일 | 고친 것 |

| `app/globals.css` | `color-scheme` · 명암비 3색 · `:focus-visible` 2px · `.skip-link` · `prefers-reduced-motion` · `text-wrap: balance` · `touch-action` |
| `app/layout.tsx` | `viewport` 에 `colorScheme` · `themeColor: #12293F` (바탕이 아니라 상단 바 색) |
| `components/shell.tsx` | 건너뛰기 링크 · `nav[aria-label]` · `main#main[tabindex=-1]` · 화면별 `sr-only` `h1` |
| `components/marks.tsx` | 분포 막대 `role="img"` + 대체 문구 · 마감 게이지 `sr-only` 문장 · 스트라이프 `focus-within` · 규격 `translate="no"` |
| `components/notice-table.tsx` | 스크롤 영역 `role/tabindex/aria-label` · `<caption>` · 행 `focus-within` |
| 화면 4개 | `Shell` 에 화면 이름 · 로딩 `role="status"` · 저장 실패 `role="alert"` · 필터 건수 `aria-live` · 상세 대조표 `role="table"` |
| `DESIGN.md` | 「접근성 최소선」 절 신설 · 색 표 3칸 수정 |

## 5. 고치지 않고 남긴 것

가이드라인에 걸리는 걸 알면서 안 고친 것들이다. **안 고친 이유가 있는 쪽이 더 쓸모 있다.**

**목록 100행을 가상화하지 않는다.**
가이드는 50개가 넘으면 가상화하라고 한다. 이 도구의 핵심이 「색 띠를 세로로 훑는 것」이라
스크롤 위치가 튀면 안 되고, 브라우저 Ctrl+F 로 공고명을 찾는 것도 막게 된다.
100행에서는 실측상 느려지지 않았다.

**필터 상태를 URL 에 안 넣는다.**
가이드는 모든 상태를 딥링크하라고 한다. 맞는 말이지만 이건 기능 변경이라 이번 범위 밖이다.
지금은 `grade` 만 읽고 쓰지는 않는다.

**상세 화면의 좌우 대조를 진짜 `<table>` 로 안 바꿨다.**
가이드는 「ARIA 보다 시맨틱 HTML 먼저」라고 하고 그게 맞다.
그런데 이 3열 grid 는 이 도구의 시그니처 화면이라 표로 옮기면 레이아웃을 다시 짜야 한다.
`role="table"` 을 붙여 절충했다. **절충이라는 걸 적어둔다.**

**다크 모드 전환 버튼을 안 붙였다.**
다크 팔레트가 통째로 정의돼 있는데 `.dark` 클래스를 붙이는 코드가 어디에도 없다.
지금 다크는 죽은 코드다. `color-scheme: light` 로 못 박아 「반쪽만 어두워지는 화면」만 막았다.
전환을 붙이는 건 기능 추가다.

**영어 카피 규칙은 적용하지 않았다.**
Title Case, 「Save API Key」식 구체적 버튼 라벨 같은 항목은 한국어 화면에 그대로 옮겨지지 않는다.

**DESIGN.md 의 낡은 줄 하나를 그대로 뒀다.**
「화면별 지침 · 오늘 브리핑」에 **「신규 카드가 나머지 둘을 합친 것보다 넓다」**고 적혀 있는데,
실제 코드는 셋을 같은 폭으로 둔다. `app/page.tsx` 주석에 왜 바꿨는지까지 적혀 있다 —
넓혀 봤더니 숫자 하나에 폭이 절반이라 카드 안이 텅 비었고, 위계는 폭이 아니라 숫자 크기로 냈다.

**코드가 옳고 문서가 낡았다.** 접근성 문제가 아니라 손대지 않았지만,
이번 작업에서 나온 문서-코드 어긋남이 이걸로 둘이다(애니메이션 금지 + 카드 폭).
지침 문서는 써두면 끝이 아니라 **같이 낡는다.**

## 6. 교안에 넣을 한 문장

> **지침 문서는 「보이는 것」만 옮긴다.**
> 색·타이포·정보 위계는 272줄짜리 DESIGN.md 가 빠짐없이 옮겼는데,
> 초점 테두리·건너뛰기·명암비 하한은 **문서에 한 줄도 없었다.**
> 화면을 보고 쓰는 문서라서, 화면에 안 나타나는 것은 쓸 계기가 없다.

곁들일 두 번째 문장이 필요하면 이것이다.

> 문서에 「애니메이션을 쓰지 않는다」고 적혀 있었고, 코드에는 전환이 세 군데 있었다.
> **문서와 코드가 갈렸는데 화면에는 아무 표시도 안 났다.** 안 보이는 항목은 어긋나도 티가 안 난다.
