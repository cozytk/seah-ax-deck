# 개발 워크플로우 실습 안내

진행 순서는 **역인터뷰로 PRD 작성 → 스킬과 레퍼런스로 디자인·개발 → Playwright MCP로 검증**입니다. 같은 프로젝트 폴더에서 이어갑니다.

## 시작 전 준비

- Claude Code의 Code 탭에서 수업용 프로젝트를 엽니다.
- `frontend-design`과 taste-skill의 `design-taste-frontend`가 현재 세션에서 사용 가능한지 확인합니다.
- Playwright MCP를 연결하고 브라우저 도구 호출이 가능한지 확인합니다.
- 업무를 설명할 샘플 자료를 준비합니다. 본 안내의 숫자는 학습용 예시입니다.

스킬 이름을 프롬프트에 쓰는 것만으로 설치되지는 않습니다. 설치되지 않았다면 [frontend-design 원본](https://github.com/anthropics/skills/tree/main/skills/frontend-design)과 [taste-skill 설치 안내](https://github.com/Leonxlnx/taste-skill#installing)를 따라 Claude Code를 대상으로 설치합니다. taste-skill의 기본 프런트엔드 스킬 이름은 `design-taste-frontend`입니다. 둘을 함께 쓰되 PRD와 내가 정한 레퍼런스 방향을 우선하도록 지시합니다.

Playwright MCP 설정은 [Microsoft 공식 안내](https://github.com/microsoft/playwright-mcp#user-content-getting-started)를 따릅니다. CLI를 쓰는 경우 공식 예시는 다음과 같습니다.

```bash
claude mcp add playwright npx @playwright/mcp@latest
```

데스크톱에서는 현재 Code 세션에서 도구가 보이고 실제 브라우저를 열 수 있는지 별도로 확인합니다. Chat 탭에만 연결된 상태로 실습을 시작하지 않습니다.

## 1. 역인터뷰로 PRD 작성

10분 동안 Claude가 묻고 내가 답합니다. 처음부터 완벽하게 설명하려고 하지 않아도 됩니다.

```text
생산실적 엑셀을 올리면 라인별 불량률을 확인하는 화면을 만들고 싶어.
바로 개발하지 말고, PRD를 쓸 수 있도록 나를 역인터뷰해줘.
사용자, 데이터 뜻, 핵심 기능, 제외 범위, 완료 조건을 물어봐.
한 번에 1~2개씩 질문하고, 애매한 답은 예를 들어 다시 물어봐.
내가 모르는 부분은 선택지와 차이를 설명해줘.
```

예를 들어 「전체 불량률 계산 방식」을 물었는데 차이를 모르면 이렇게 되묻습니다.

```text
라인별 불량률을 평균하는 것과 수량 합계로 계산하는 것은 어떻게 달라?
생산량이 서로 다른 두 라인으로 설명해줘.
```

수업 예시는 A라인 생산량 100·불량수 4, B라인 생산량 200·불량수 2입니다. 전체 불량률은 `6 ÷ 300 = 2%`, A라인만 선택하면 `4 ÷ 100 = 4%`입니다. 이 기준을 선택했다면 PRD에도 남깁니다.

```text
지금까지 합의한 내용을 PRD.md로 정리해줘.
목적·사용자·데이터 정의·핵심 기능·제외 범위·완료 조건을 담아줘.
미정인 내용은 지어내지 말고 따로 표시해줘.
개발을 막는 미정 항목부터 다시 질문해줘. 아직 코드는 만들지 마.
```

**확인:** PRD를 읽고 내가 정하지 않은 기능, 계산식, 제외 범위를 고칩니다. 생산량 0과 필수 열 누락 등 예외도 결정합니다. 짝이 PRD만 읽고 「어떤 동작을 해서 어떤 결과가 나오면 완료인지」 말할 수 있으면 다음으로 넘어갑니다.

## 2. 레퍼런스와 스킬로 디자인·개발

5분 동안 [Dribbble](https://dribbble.com/) 등에서 만드는 화면과 비슷한 사례를 찾습니다. 대시보드라면 `dashboard`, 표가 중심이라면 `data table`로 검색해 보세요.

전체 배치가 마음에 드는 화면 1장, 세부 모양을 참고할 화면 1~2장을 캡처합니다. Windows는 `Win + Shift + S`, macOS는 `Shift + Command + 4`를 사용합니다. 캡처를 저장하는 단계까지 마칩니다.

프로젝트 안에 `reference` 폴더를 만들고 아래처럼 저장합니다. 별도 디자인 문서는 작성하지 않습니다.

```text
내 프로젝트/
├── PRD.md
└── reference/
    ├── dashboard.png
    └── table.png
```

Claude에게 이미지가 읽히는지 먼저 확인합니다.

```text
reference 안의 이미지들을 열고, 각 이미지의 특징을 설명해줘.
```

그다음 원하는 부분을 짚습니다.

```text
reference/dashboard.png의 왼쪽 메뉴와 상단 지표 배치를 참고해줘.
reference/table.png에서는 행 간격과 숫자 정렬을 참고해줘.
색과 여백도 비슷한 느낌으로 맞추되,
문구와 데이터, 기능은 PRD.md에 맞춰줘.
```

레퍼런스를 주면 원하는 배치와 분위기에 가깝게 구현하도록 방향을 잡을 수 있습니다. 첫 결과를 보고 다른 부분을 구체적으로 짚어 조정합니다.

```text
PRD.md와 reference/의 이미지를 읽어줘.
frontend-design과 taste-skill(design-taste-frontend)을 사용해 구현해줘.
별도의 디자인 문서는 만들지 말고 레퍼런스를 참고해 바로 개발해줘.
먼저 엑셀 업로드 → 전체 불량률 → 라인 필터 흐름을 완성해줘.
실행한 뒤 접속 주소와 확인할 동작을 알려줘.
```

**확인:** 실제 스킬을 읽었는지 작업 기록을 보고, 핵심 동작이 있는 앱을 실행합니다. 방향이 다르면 중간에 멈추고 재지시합니다. 기능을 한꺼번에 늘리기보다 업로드부터 필터까지 한 흐름을 먼저 완성합니다.

## 3. Playwright MCP로 검증

검증 자료부터 만듭니다. 앱과 별개로 파일을 열어 두 행의 값과 열을 확인합니다.

```text
검증용 엑셀 두 개를 만들어줘. 열 이름은 PRD.md의 정의를 따라줘.
sample-ok.xlsx: A라인 생산량 100, 불량수 4 / B라인 생산량 200, 불량수 2.
sample-missing.xlsx: 같은 데이터에서 불량수 열을 뺀 파일.
저장한 파일의 위치를 알려줘. 다른 필수 열은 유효한 값으로 채워줘.
```

실제 앱 주소와 두 파일의 경로를 알려 주고 요청합니다.

```text
실행 중인 앱을 Playwright MCP로 열어 PRD.md의 완료 조건을 검증해줘.
샘플 파일을 업로드하고 전체 2%, A라인 선택 시 4%인지 확인해줘.
필수 열이 빠진 파일도 올려 안내가 나오는지 확인해줘.
각 항목의 기대값·실제 결과·통과 여부와 화면 캡처를 보여줘.
실패하면 원인을 고치고, 같은 동작을 다시 실행해줘.
```

**확인:** 실제 MCP 도구 호출과 결과를 봅니다. 연결이나 파일 접근 문제로 실행하지 못했다면 미검증입니다. 정상 업로드, 필터, 오류 안내, Tab 조작을 확인하고, 같은 화면 크기의 캡처를 레퍼런스와 나란히 비교합니다.

수정 요청에도 재검증 조건을 붙입니다.

```text
A라인을 선택해도 전체 값 2%가 그대로 보여.
필터에 따라 표시값이 바뀌도록 고쳐줘.
Playwright MCP로 같은 샘플을 다시 올려 A라인 4%를 확인하고,
필터를 전체로 바꾸면 2%로 돌아오는지도 확인해줘.
```

5분 독립 실습에서는 자기 PRD의 완료 조건 하나를 골라 입력 자료·행동·기대 결과가 들어간 검증 지시를 직접 씁니다.

## 마무리

PRD의 핵심 흐름이 통과하고, 레퍼런스와 비교한 결과 및 실패·미검증 항목을 확인한 뒤 배포합니다. 배포 주소에서도 핵심 동작을 다시 확인합니다. 예약 실행은 그다음 선택 확장입니다.

수주 레이더에도 같은 순서를 씁니다. 역인터뷰에서 판정 기준을 정하고, 목록 화면을 참고해 구현한 뒤, Playwright MCP로 필터·원문 링크·실패 안내를 검증합니다. 「새 공고 없음」과 「수집 실패」는 따로 재현하며, 원문을 읽지 못하면 판단불가로 남깁니다. 실제 수집 성공 여부는 수집 로그와 원문도 함께 확인합니다.
