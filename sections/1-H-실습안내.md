# 1-H 실습 안내 · 같은 부탁, 다른 도구

15분. 같은 요청을 두 번 보냅니다. 한 번은 도구를 정하지 않고, 한 번은 Playwright MCP를 지정해서. 목표는 결과가 왜 갈리는지와 그 차이의 책임이 누구에게 가는지를 수강생이 자기 말로 설명하는 것입니다.

A는 수강생이 각자 따라 합니다. 도구가 스스로 멈추기 때문에 안전합니다. B는 강사가 시연합니다. robots.txt가 전면 금지한 사이트에 수강생 전원이 동시에 접속하는 것은 이 실습의 취지와 어긋납니다.

## 준비

수업 전에 규칙을 먼저 화면에 띄웁니다.

```bash
curl -s https://news.naver.com/robots.txt
```

2026년 9월 10일 기준 첫 두 줄이 `User-agent: *` / `Disallow: /` 입니다. 아래에 GPTBot·ClaudeBot·PerplexityBot 등 AI 수집기를 이름으로 막는 줄이 이어집니다. 「모든 봇에게 모든 경로를 금지한다」는 뜻이라고 읽어 줍니다.

Playwright MCP는 **B 직전에** 붙입니다. A 시점에 이미 붙어 있으면 Claude Code가 A에서 알아서 Playwright로 넘어가 버려 대조가 안 됩니다. 붙인 채로 A를 해야 한다면 A는 MCP 없이 시작합니다.

```bash
claude --strict-mcp-config
```

Node.js 18 이상이 필요합니다. 처음 붙이면 `npx`가 패키지를 내려받느라 첫 호출이 느립니다.

## 실험 A · 그냥 시킨다

```text
https://news.naver.com/section/101 네이버 뉴스 경제 탭에서 최신 뉴스 10개 제목과 링크를 가져와줘.
```

강사 노트북에서 실측한 흐름은 두 갈래였습니다. 어느 쪽이 나와도 됩니다.

- **대화형 세션** — `Fetch` 시도 → `Error: Claude Code is unable to fetch from news.naver.com` → Chrome 확장으로 다시 시도 → `This site is not allowed due to safety restrictions` → 「웹 검색으로 대체 / 다른 사이트 / 중단」 선택지를 내밉니다. **중단**을 고릅니다.
- **헤드리스 세션** — 같은 `Fetch` 오류 뒤에 Bash로 `curl`을 시도합니다. 이때 User-Agent를 `Mozilla/5.0 … Chrome/120.0`으로 위장해 넣습니다. 승인 카드가 뜹니다.

승인 카드가 뜨면 거기서 멈추고 설명합니다. 「Anthropic 쪽 도구는 robots.txt를 보고 멈췄다. 지금 Claude가 하려는 건 그 울타리 밖으로 나가는 것이고, 승인하는 순간 책임은 나에게 온다.」 그리고 **거부**합니다. 실패 화면을 지우지 말고 그대로 둡니다.

프롬프트에 「우회하지 마」를 넣지 않습니다. Claude가 스스로 우회를 제안하는 장면이 「도구 정책 vs 사용자 결정」의 경계를 가장 잘 보여줍니다.

## 실험 B · 도구를 지정한다

세션을 나가서 붙이고 다시 들어옵니다.

```bash
claude mcp add playwright -- npx @playwright/mcp@latest
claude
```

`/mcp`에서 playwright가 `connected`로 보이는지 확인한 뒤 보냅니다.

```text
Playwright MCP로 https://news.naver.com/section/101 에 접속해서 최신 뉴스 10개 제목과 링크를 가져와줘.
```

예상 흐름은 `browser_navigate` → `browser_snapshot` → 제목 10개 추출입니다. 오류가 없고, robots.txt 언급도 없습니다. 끝나면 한 줄 더 묻습니다.

```text
방금 접속할 때 robots.txt를 확인했어?
```

「확인하지 않았다 / Playwright에는 그런 검사가 없다」는 답이 이 실습의 결론입니다. Playwright MCP 공식 문서에는 robots.txt라는 단어가 없습니다.

## 대조 정리

|  | A | B |
|---|---|---|
| 프롬프트 | 도구 미지정 | Playwright 지정 |
| 요청 주체 | Anthropic 쪽 fetcher · Chrome 확장 | 내 PC의 Chromium |
| robots.txt | 확인 → 중단 | 확인 안 함 |
| 결과 | 실패 + 대안·우회 제안 | 성공 |
| 책임 | Anthropic이 회피 | 사용자 |

## 반론 준비

「그럼 B로 매일 수집해도 되나요?」가 나옵니다. 답은 「되냐」가 아니라 「누구 책임이냐」입니다. 기준은 규모(한 번 보기 vs 매일 수백 건), 약관(자동 수집 금지 조항), 저장·재이용(내부 참고 vs 재배포)입니다. 실습서 2일차 1교시 「코드 한 줄 쓰기 전에」 표(robots.txt · 이용약관 · 공개 API · 로그인)로 연결합니다. 이 연결이 실습을 「우회 방법 강의」로 읽히지 않게 하는 안전장치입니다.

## 강사 진행 메모

A 5분, B 5분, 정리·반론 5분. A에서 수강생 화면마다 갈래가 다를 수 있으니 「멈춘 자리」와 「무엇을 제안했는지」 두 가지만 확인하게 합니다. 정리표는 B가 끝난 직후 띄웁니다. 결론 문장은 강사가 말하지 않고 B의 마지막 답변이 대신하게 둡니다.

끝나면 `claude mcp remove playwright`로 떼거나 `/mcp`에서 끄게 안내합니다. 안 쓰는 서버는 매 세션 맥락을 먹습니다.
