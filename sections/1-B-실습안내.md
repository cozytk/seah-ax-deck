# 1-B 실습 안내 · 쓰는 도중에 방향 바꾸기

5분 동안 회의 안내문 하나를 고칩니다. 목표는 Claude의 응답을 직접 멈추고, 같은 대화에서 지시를 바꿔 원하는 결과를 받는 것입니다.

## 준비

Claude 데스크톱 앱의 Code 탭에서 새 대화를 엽니다. 프로젝트 선택이 필요하면 수업용 폴더를 선택하세요. 별도 자료는 필요 없습니다.

최종 결과는 팀 메신저에 보낼 회의 안내 3줄입니다. 처음에는 일부러 길게 요청합니다.

## 1. 긴 글을 요청하고 중간에 멈추세요

아래 내용을 보냅니다.

```text
내일 오후 2시, 3층 회의실에서 생산실적 회의를 해.
팀원들은 지난주 생산량과 불량률을 준비해 와야 해.
이 내용을 격식 있는 안내문으로 30문단 이상 길게 써줘.
파일이나 도구는 쓰지 말고 대화에만 작성해줘.
```

첫 문단이 나오면 **Esc를 두 번** 누릅니다. 새 글이 더 나오지 않는지 확인하세요. 이미 나온 글이 남아 있어도 정상입니다.

중단은 Esc 한 번으로도 됩니다. Esc 두 번으로 되감기 메뉴가 열렸다면 취소하고 입력창으로 돌아오세요. 응답이 계속되면 정지 버튼을 누릅니다. 두 번 누르는 것만으로 파일이나 대화가 자동 복구되는 것은 아닙니다.

## 2. 같은 대화에서 원하는 결과를 다시 말하세요

회의 정보를 다시 붙이지 않고, 아래 지시만 보냅니다.

```text
방향을 바꿀게. 긴 안내문은 그만 쓰고,
앞서 준 회의 정보를 팀 메신저용으로 정확히 3줄로 써줘.
1줄은 일시, 2줄은 장소, 3줄은 준비할 내용.
서론이나 맺음말은 빼줘.
```

## 3. 직접 확인하세요

- 새 답변이 정확히 3줄인가요?
- 내일 오후 2시, 3층 회의실, 지난주 생산량과 불량률이 모두 들어 있나요?
- 처음의 회의 정보를 다시 입력하지 않아도 내용이 이어졌나요?

조건을 놓쳤으면 빠진 부분만 짚어 한 번 더 요청하세요. 완료 기준은 **직접 중단하고 → 같은 대화에서 재지시하고 → 결과를 확인하는 것**입니다.

마지막으로 옆 사람에게 말해 보세요. 「다음에 방향이 어긋나면, 언제 멈추고 무엇을 다시 말하겠어요?」

## 강사 진행 메모

첫 1분은 목표와 중단 동작을 시연하고, 3분은 학생이 실행하며, 마지막 1분은 결과 확인에 씁니다. 이 사례는 모델의 실수를 기다리는 실험이 아니라 사용자가 요구를 바꿔도 된다는 경험을 만드는 연습입니다.

응답이 너무 빨리 끝났으면 같은 대화에서 재지시부터 완료하게 합니다. 이후 긴 설명을 추가 요청해 출력이 시작되자마자 중단을 다시 경험하게 하세요. 전송 전에 새 지시를 복사해 두면 진행이 수월합니다.

데스크톱 공식 단축키 표는 Esc 중단을 안내합니다. CLI의 Esc 두 번은 되감기 메뉴를 여는 동작입니다. 수업에서는 메뉴가 열리면 취소하며, 되감기나 파일 복구는 선택하지 않습니다. 중단해도 이미 수행한 파일 수정 등이 자동 취소되지는 않습니다.
